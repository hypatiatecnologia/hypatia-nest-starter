# Exemplo 07 — go/rule.mdc + go-security.mdc
# Error handling idiomático, context.Context, queries parametrizadas

**Rules ativas:** `go/rule.mdc` (auto-attach via `**/*.go`), `go-security.mdc` (auto-attach via `**/*.go`)

---

## Prompt de entrada

```
Crie um handler HTTP em Go que recebe GET /users/{id}/orders,
busca os pedidos do usuário no banco e retorna JSON.
```

---

## Output CORRETO (esperado)

```go
// internal/handler/orders.go

package handler

import (
    "errors"
    "net/http"

    "github.com/go-chi/chi/v5"

    "myapp/internal/domain"
    "myapp/internal/service"
)

type OrderHandler struct {
    orders service.OrderService // porta — interface, não concretização
}

func NewOrderHandler(orders service.OrderService) *OrderHandler {
    return &OrderHandler{orders: orders}
}

func (h *OrderHandler) GetUserOrders(w http.ResponseWriter, r *http.Request) {
    ctx := r.Context() // ✅ context propagado — cancelamento, tracing, timeout

    userID := chi.URLParam(r, "id")
    if userID == "" {
        writeError(w, http.StatusBadRequest, "invalid_user_id", "User ID is required")
        return // ✅ early return — sem else profundo
    }

    // ✅ ownership verificado no serviço antes de retornar dados
    orders, err := h.orders.FindByUserID(ctx, userID)
    if err != nil {
        var domainErr *domain.DomainError
        if errors.As(err, &domainErr) { // ✅ errors.As no boundary
            writeError(w, domainErr.HTTPStatus(), domainErr.Code, domainErr.Message)
            return
        }
        // ✅ erro inesperado — log servidor, genérico ao cliente
        logError(r, err, "unexpected error in GetUserOrders")
        writeError(w, http.StatusInternalServerError, "internal_error", "An unexpected error occurred")
        return
    }

    writeJSON(w, http.StatusOK, orders)
}
```

```go
// internal/repository/order_postgres.go

package repository

import (
    "context"
    "database/sql"
    "fmt"

    "myapp/internal/domain"
)

type PostgresOrderRepository struct {
    db *sql.DB
}

func (r *PostgresOrderRepository) FindByUserID(ctx context.Context, userID string) ([]domain.Order, error) {
    // ✅ query parametrizada — proibido fmt.Sprintf com userID
    rows, err := r.db.QueryContext(ctx,
        "SELECT id, user_id, product_id, amount, status FROM orders WHERE user_id = $1",
        userID, // ✅ placeholder $1, não interpolação
    )
    if err != nil {
        return nil, fmt.Errorf("findByUserID: %w", err) // ✅ wrap com %w para errors.Is/As
    }
    defer rows.Close()

    var orders []domain.Order
    for rows.Next() {
        var o domain.Order
        if err := rows.Scan(&o.ID, &o.UserID, &o.ProductID, &o.Amount, &o.Status); err != nil {
            return nil, fmt.Errorf("scan order: %w", err)
        }
        orders = append(orders, o)
    }
    return orders, rows.Err()
}
```

**Por que está correto:**
- `context.Context` propagado de `r.Context()` — permite cancelamento e tracing.
- `errors.As` no boundary do handler — mapeia `DomainError` para HTTP sem vazar detalhes.
- Query 100% parametrizada com `$1` — zero risco de SQL injection.
- `fmt.Errorf("...: %w", err)` — wrap idiomático que preserva cadeia para `errors.Is`/`errors.As`.
- Handler não conhece SQL — só a interface `service.OrderService` (DIP).
- Early return após cada erro — nesting máximo: 2 níveis.

## Output INCORRETO (proibido pelas rules)

```go
// ❌ Viola go/rule.mdc e go-security.mdc
func GetOrders(w http.ResponseWriter, r *http.Request) {
    userID := r.URL.Query().Get("user_id") // ❌ sem validação — pode ser vazio ou malicioso

    // ❌ SQL injection — fmt.Sprintf com input externo direto
    query := fmt.Sprintf("SELECT * FROM orders WHERE user_id = '%s'", userID)
    rows, err := db.Query(query) // ❌ db global — estado compartilhado, sem context
    if err != nil {
        // ❌ panic em handler de request — derruba o servidor
        panic(err)
    }

    // ❌ sem context.Context — sem suporte a cancelamento nem tracing
    // ❌ sem errors.As — erro de infra vaza ao cliente
    json.NewEncoder(w).Encode(rows) // ❌ rows não é serializável diretamente
}
```

**Por que está errado:**
- `fmt.Sprintf` com `userID` em SQL → SQL injection (CWE-89, A03 OWASP).
- `panic` em handler → derruba o servidor inteiro, sem recuperação.
- `db` global sem `context` → sem cancelamento, sem timeout, sem tracing.
- Sem `errors.As` → erro de banco exposto diretamente ao cliente.
- Sem validação de `userID` → qualquer string, incluindo payloads de injeção.
